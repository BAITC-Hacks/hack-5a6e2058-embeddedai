# Деплой на подготовленный Ubuntu VPS

Caddy обслуживает `cca8f159.nip.io`, HTTPS уже настроен. Приложение слушает
`127.0.0.1:3000`. Статический web-root — только `web/dist`; результаты доступны
через API по непредсказуемому идентификатору запуска.

1. Подготовить Python 3.12 и uv. Python должен быть доступен служебному пользователю
   вне `/root`, например `/opt/money-graph-python` через `UV_PYTHON_INSTALL_DIR`.
2. Собрать frontend локально: `npm --prefix web ci && npm --prefix web run build`.
3. Перенести `src/`, `config/`, `web/dist/`, `deploy/`, `pyproject.toml`, `uv.lock`
   и `.python-version` в `/opt/money-graph`. Не включать private/, .env, data/.
4. Выполнить `uv sync --frozen --no-dev --python 3.12` в каталоге приложения.
5. Создать системного пользователя moneygraph без shell, каталог
   `/var/lib/money-graph` с владельцем moneygraph и правами 700.
6. Установить `money-graph.service` в `/etc/systemd/system/`, затем:

```bash
systemctl daemon-reload
systemctl enable --now money-graph
curl -f http://127.0.0.1:3000/health
curl -f https://cca8f159.nip.io/health
```

Сервис запускает синтетический пример; исходные данные организаторов публично
не размещаются. Каталог результатов не находится в web-root.

При обновлении остановить службу, сохранить предыдущий релиз, заменить код и
собранный интерфейс, выполнить `uv sync --frozen --no-dev`, затем запустить и
проверить сценарий. Каталог `/var/lib/money-graph` сохраняется.

Диагностика:

```bash
systemctl status money-graph --no-pager
journalctl -u money-graph -n 60 --no-pager
caddy validate --config /etc/caddy/Caddyfile
```

На подготовленном VPS тело запроса Caddy ограничено
до 32 МБ (`request_body { max_size 32MB }`). API также проверяет лимит каждого
файла и количество записей; обрабатывает один расчёт за раз на процесс.
Это демо без корпоративной авторизации. Публично используйте синтетические
данные, реальные чувствительные сведения анализируйте локально.

При старте фиксируется конфигурация правил. После её изменения перезапустите
службу. Начальный набор повторно используется только при совпадении режима
(синтетика или явно заданный `--data`), правил и SHA-256 явно заданных исходников.
При повреждении метаданных или результата начальный набор пересчитывается.
Запуск без `--data` всегда выбирает синтетический режим, даже если раньше служба
работала с другими данными.

Сохранённые расчёты прежней конфигурации возвращают HTTP 409 и требуют повторной
загрузки исходных файлов для просмотра. Их опубликованные CSV по адресам
`/api/runs/{run_id}/exports/{filename}` остаются доступны до обычной очистки,
в том числе при повреждённом `result.json`. Не выдавайте старые результаты за
новый расчёт. Очистка выполняется только после успешной публикации новой загрузки:
сохраняются текущий начальный набор и до 20 загрузок не старше 24 часов.

## Необязательный AI

Служба читает `/etc/money-graph/assistant.env`, если файл существует. Ключи
никогда не входят в архив релиза. Сохраните ключ отдельно вне web-root,
например в `/etc/money-graph/openai_api_key.txt` (root:moneygraph, права 640).
Каталог `/etc/money-graph` — root:moneygraph, 750. В `assistant.env` (root, 600):

```text
OPENAI_API_KEY_FILE=/etc/money-graph/openai_api_key.txt
OPENAI_MODEL=gpt-4.1-mini-2025-04-14
MONEY_GRAPH_ASSISTANT_TOKEN=<отдельный случайный код доступа>
```

Подставьте свой код, перезапустите службу и проверьте `/api/assistant/status`.
Код вводится только в поле ассистента; его не следует встраивать в JS или URL.
Без конфигурации платная функция отключена, остальные возможности работают.
Сохраняйте `assistant.env` при обновлении; секреты не копируются в GitHub.
