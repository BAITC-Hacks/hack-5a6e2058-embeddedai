# Аудит требований ТЗ: разделы 7–10

Состояние реализации: приложение **0.8.0**, правила **2.2**, временные паттерны
**1**. Проверка выполнена по перечню обязательных функций, дополнений, ограничений
и артефактов организаторов. Здесь каждому пункту сопоставлена реализация и способ
проверки; предполагаемая оценка жюри не заявляется.

На официальных исходниках независимый проверяющий скрипт подтвердил
**2 248 узлов, 88 сообществ и TOP 50**. Он проверяет файлы отдельно от алгоритма,
сверяет CSV между собой и с исходными Parquet. Успешная проверка контракта
не означает доказанную правильность эвристических ролей: эталонных меток нет.

Единственная команда анализа, из корня checkout:

```text
uv run --frozen --no-dev python analyze.py --data ./data/data --out ./artifacts
```

Независимая проверка уже созданных артефактов, без повторного расчёта ролей:

```text
uv run --frozen --no-dev python scripts/check_submission.py --out ./artifacts --data ./data/data
```

Вариант проверяющего скрипта без `--data` использует только стандартную библиотеку
Python, но не подтверждает покрытие сырых исходников. Это дополнительная проверка,
а не обязательный ручной шаг пайплайна: сама команда анализа проверяет свои выгрузки.

## 8. Все восемь дополнительных возможностей

| Пункт ТЗ | Реализация и фактические границы | Проверка |
|---|---|---|
| **8.1. Обрыв на четвёртом колене** | `depth=4` без выхода помечается как цензурированная граница. Отсутствие выхода не даёт таким узлам роли terminal/consolidator; потоковый transit также требует наблюдаемости. Seed не получают потоковую роль из неполного отношения входа и выхода. Для всех 444 граничных узлов это ограничение сохраняется. Настоящая конечность за пределами выгрузки не устанавливается. | `features.compute`, `roles.classify`; `test_official_contract_if_present`, `test_role_hypotheses_and_observation_limits`. В карточке указана причина и следующий запрос данных. |
| **8.2. Транзит за 1–2 дня, всплески, синхронные поступления** | FIFO сопоставляет наблюдаемые входы с выходами через 1–2 календарных дня без повторного использования суммы. Внутридневной порядок не предполагается. Всплеск: **>max(3×медиана, медиана+5)** операций за активный день при ≥7 активных дней. Синхронная дата: ≥3 различных плательщиков. Указаны фактические даты, числа и суммы; недостаточная история обозначается явно. На официальном наборе: **13** узлов со всплесками, **38** с синхронными датами. | `temporal.py`; тесты `test_temporal_cannot_reuse_funds_or_infer_same_day_order`, `test_temporal_reversed_or_expired_receipts_are_not_transit` и [test_temporal_patterns.py](../tests/test_temporal_patterns.py). Формулы и ограничения — [METHODOLOGY.md](METHODOLOGY.md#всплески-и-календарная-синхронность). |
| **8.3. Повторяемые маршруты и возвратные потоки** | Найдены наблюдаемые направленные пути от seed, двусторонние связи, короткие циклы и A→B→C, где на каждом звене ≥2 операций. Количество сочетаний A→B→C точно; показывается до 10 примеров среди сильнейших звеньев. До пяти циклов, длина в карточке ≤5 рёбер. Повторяемость отдельных звеньев не выдаётся за доказанное повторение всей цепочки или возврат тех же денежных единиц. | `investigation.node_evidence`; `test_seed_paths_and_cycles_contain_only_observed_directed_edges`, `tests/test_graph_query.py`. Карточка выводит исходные рёбра с суммой и числом операций. |
| **8.4. Дробление и аномальные профили относительно колена** | Профили сравниваются с активными узлами того же depth: `x>Q3+3×IQR`, минимум 20 узлов и IQR>0. Для повторных малых сумм: ≥3 точно равных перевода за день/направление, сумма ≤ собственного Q1, минимум 8 переводов в направлении. На официальном наборе такие группы есть у **18** узлов. Это повод проверить гипотезу дробления; обычные платежи также возможны. **Дробление ниже 5 000 KZT не обнаруживается:** таких операций нет в выгрузке. Неизвестные банковские пороги не придумываются. | `anomalies.py`, `temporal.py`; `tests/test_anomalies.py`, `tests/test_temporal_patterns.py`: явный отказ при малой группе, строгие границы, точное равенство сумм, отдельные даты/направления, исключение самопереводов. |
| **8.5. Устойчивость при изъятии top-N** | Виртуально удаляются N=1…20 узлов; сравниваются TOP, степень и 20 случайных выборок с seed=42. Считаются компоненты, крупнейшая компонента, потеря связности среди оставшихся узлов и оборот затронутых рёбер. Направление при оценке связности не учитывается. Это статический сценарий, не прогноз блокировки денег или реакции сети. Дополнительно доступны чувствительность весов и [устойчивость ролей/сообществ](ROBUSTNESS.md). | `investigation.resilience`, `robustness.py`; `test_removal_measures_fragmentation_among_surviving_nodes_not_removed_nodes`, `tests/test_robustness.py`. Вкладка «Проверки». |
| **8.6. AI-ассистент со ссылками на узлы** | Общая строка наверху; вопрос, выбранная группа, карточка, фильтры, текущая страница очереди и история определяют контекст. Справка Markdown скачивается без LLM; содержит источник и SHA-256. Отдельный скрипт создаёт карточки для выбранных gid из результата. | `web/src/analysis.ts`, [scripts/demo_nodes.py](../scripts/demo_nodes.py), [DEMO_NODES.md](DEMO_NODES.md). ## 9. Запреты и обязательные ограничения

| Запрет | Как соблюдён |
|---|---|
| Хардкод «правильных» gid | Признаки и роли вычисляются из входа; исходный период и число узлов не зашиты в алгоритм. Конкретные gid в демо-документах — разобранные примеры, не ветвления расчёта. Генератор `demo.py` содержит отдельные синтетические идентификаторы. Тест перестановки исходных строк подтверждает одинаковые CSV. |
| Чёрный ящик вместо роли | Опубликованы правила, пороги, порядок совпадений, поправки наблюдаемости и формула приоритета. У каждого узла есть evidence; у каждой позиции TOP — why. Модель LLM не присваивает роли и не управляет основным рейтингом. |
| Внешнее обогащение/выдуманные атрибуты | Loader выбирает только поля схемы организаторов. ФИО, ИИН, возраст, доход, организация не требуются и не достраиваются. Лишние колонки не могут подменить расчётные метрики. Тест `test_extra_columns_cannot_leak_attributes_or_override_metrics` подтверждает это. Внешний LLM получает производные факты для объяснения, а не используется как источник атрибутов. |
| Обязательный облачный кластер, GPU или платный сервис | Основной анализ, три CSV, офлайн HTML и интерфейс выполняются на локальном CPU без ключа. Платный LLM — только дополнительный интерактивный ассистент. Нет обучения GPU-моделей или обязательной облачной БД. |

| Требование | Реализация и предел утверждения |
|---|---|
| **Explainability** | Формулы, основания, реальные метрики, пороги и вклад в приоритет доступны в CSV/карточках/методике. `role_score` не называется вероятностью преступления; чувствительность не называется accuracy. |
| **Приватность** | Используются обезличенные строковые int64 gid. Публичное демо запускается на синтетике; исходные данные организаторов и секреты не включаются в публичный релиз. AI передаёт провайдеру вопрос, ограниченный контекст и запрошенные производные факты; это раскрыто в интерфейсе и документации. Без AI внешней передачи данных анализа нет. |
| **Осторожность формулировок** | Роли, сообщества, временные совпадения и повторные суммы — гипотезы для проверки. Путь не доказывает происхождение денег, нулевой выход — полный остаток, а структурное сообщество — преступную организацию. Нет автоматических решений о блокировке. |
| **Производительность ≤5 минут** | Предварительный локальный замер алгоритма после изменений: **4.107 с**, официальный объём 2 248 / 3 119 / 4 840, Linux. Это не время чистой установки и не полный замер команды. Полный замер и фактически выполненные проверки фиксируются отдельно в [VALIDATION_08.md](VALIDATION_08.md). |
| **Локальная инфраструктура; интернет только для необязательного LLM** | После установки зависимостей анализ и просмотр работают без сети; JS/CSS включены в сборку, CDN нет. Первая установка uv/Python/пакетов требует сети либо заранее подготовленных локальных пакетов. Основной CLI не открывает LLM API. Наличие инструкции не выдаётся за проверку любой произвольной чистой ОС. |
| **Стек** | Python 3.12, pandas/PyArrow, NumPy/SciPy, NetworkX, FastAPI; TypeScript/Cytoscape/Vite для интерфейса. Зависимости закреплены `uv.lock` и `web/package-lock.json`; одна функция анализа используется CLI и API. |
| **План для ≈1 млн узлов** | [README](../README.md#масштабирование-за-миллион-узлов) и [SCALING.md](SCALING.md) описывают пакетный ввод, CSR/CSC, приближённые метрики, фоновые задачи и выборки для интерфейса. **Обработка миллиона узлов не реализована и не проверена.** Текущие лимиты: 10 000 узлов, 50 000 рёбер, 100 000 операций, 128 МБ распакованного объёма на файл; дополнительно 10 МиБ на файл веб-загрузки. |

Команды подготовлены для Linux, macOS и Windows PowerShell. В этом аудите
проверки выполнялись на **Linux**; фактического запуска на Windows/macOS не было.
CI отключён по решению владельца; переносимость нельзя подтверждать неисполненной
матрицей CI. Ошибки установки и альтернативы описаны в [RUNNING.md](RUNNING.md).

## Зафиксированные проверки этого аудита

Независимая сверка с сырыми файлами завершилась `status=success`:
покрытие узлов, схемы и заполненность CSV, диапазоны score, кластеры, глобальный
порядок TOP, согласованность JSON и SHA-256 исходников. Все три обязательных CSV
после добавления временных проверок и исправления сумм остались побайтно прежними:

| Файл | SHA-256 |
|---|---|
| `nodes_roles.csv` | `ab8677382abfdedcfbd429b404be38729702cee3d794e29098aeb8787492c127` |
| `clusters.csv` | `73c06950a8023a971dbeee1ad30e0d7a297692730902b4efa489ea4b74b8dc20` |
| `top_nodes.csv` | `2450394e05c4309ec3b1ea06b5bafe00ac5f140b8224c55972a6ce5c23c6497d` |

Целевая проверка `test_temporal_patterns.py`, `test_investigation.py`,
`test_scaling.py`, `test_analysis.py` прошла: **43 теста**, включая девять новых
регрессий. Они проверяют границы новых правил, отказы при малой выборке,
настоящие рёбра, запрет повторного использования сумм и денежную точность.
В исправленных Python-модулях прошли Ruff и mypy.

Результаты полной проверки, чистой установки и актуальной браузерной проверки
публикуются только после их выполнения в [VALIDATION_08.md](VALIDATION_08.md).
Этот документ не заменяет журнал фактически исполненных проверок.
