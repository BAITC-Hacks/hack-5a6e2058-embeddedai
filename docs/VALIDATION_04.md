# Проверка версии 0.4.0 — 23 сентября 2026

В этой версии добавлены отдельный Python-вход для жюри, переносимые команды,
оптимизации без изменения правил 2.1 и светлая/тёмная/системная темы.
Предыдущая полная сверка ТЗ и официального набора сохранена в
[VALIDATION.md](VALIDATION.md); новые команды — [RUNNING.md](RUNNING.md).

## Единый quality gate

Выполнено на Linux:

```text
uv run --frozen python scripts/verify.py
```

Код завершения 0. Ruff/format проверили 29 Python-файлов, mypy — 13 модулей;
**146 pytest-тестов прошли за 15,46 с**. Пройдены Biome, TypeScript, Vite production
build и smoke собранной страницы/API/CSV. **18 Playwright-сценариев прошли
за 39,6 с**. Время установки зависимостей в эти числа не включено.
Предупреждения Starlette и pandas об экстремальных int64 остаются видимыми,
как в предыдущем аудите; идентификаторы проходят round-trip без округления.

Новые проверки CLI включают отдельные переименованные файлы, пробелы/кириллицу
в путях, неполные и смешанные аргументы, защиту исходников, отсутствие зависимостей,
UTF-8 при legacy-кодировке процесса, точность экспорта requirements из lockfile
и остановку runner при первой ошибке с сохранением exit code. Подтверждён
режим `--backend-only`, которому не требуется Node.js.

Четыре новых браузерных сценария проверяют:

- применение сохранённой темы до загрузки основного bundle, включая CSP `script-src 'self'`;
- реакцию на тему ОС, приоритет ручного выбора, клавиатуру и запрет localStorage;
- панели/диалоги/SVG, контраст текста на основных поверхностях ≥4,5:1 и мобильный экран;
- PNG с фоном активной темы и сохранением цветов ролей.

## Независимая установка через pip

Создана пустая Python 3.12 venv, выполнено:

```text
python -m pip install --require-hashes -r requirements.txt
```

Все runtime-пакеты установлены по точным версиям и хешам. В этой среде без
установки самого проекта запущен `analyze.py` из другого рабочего каталога.
Три Parquet скопированы в разные каталоги и переименованы с кириллицей/пробелами;
переданы через `--nodes`, `--edges`, `--transactions`. В дочернем процессе
`PATH` был пуст: uv и Node не участвовали в расчёте.

Код завершения 0, внешний wall-clock **5,556 с**, включая Python startup,
копирование явно переданных файлов и запись CSV/JSON, после установки пакетов.
Получены все **2248 узлов**, 88 сообществ и TOP 50. Три CSV побайтно совпали
с `artifacts/`:

```text
nodes_roles.csv  bc49d894f34c76c3ec62003a8c6913ea21597fe940b957c54b3117899ac902e5
clusters.csv     73c06950a8023a971dbeee1ad30e0d7a297692730902b4efa489ea4b74b8dc20
top_nodes.csv    ef635efe952ca125a3a94a7cf1b9b793901588db4be7fc6c2aa976fd9a4af923
```

UTF-8 задан явно при чтении/записи JSON, CSV использует LF на всех ОС. SHA-256
читается потоком; совпадение с тремя сохранёнными хешами источников проверено.

Отдельно выполнена точная команда README через uv с `--data ./data/data`:
**5,833 с** от запуска процесса до готовых файлов (report: 4,377 с). Три CSV
снова побайтно совпали с предыдущей опубликованной версией.

## Переносимость и фактический статус CI

Настроена [.github/workflows/verify.yml](../.github/workflows/verify.yml):
Python 3.12 на Ubuntu 24.04, Windows и macOS, backend quality gate, CLI с тремя
файлами и сравнение результатов CSV; на Linux также frontend и Chromium.
Actions закреплены по commit SHA, uv — по версии, пакеты — по lockfiles.

Первый [запуск CI](https://github.com/BAITC-Hacks/hack-5a6e2058-embeddedai/actions/runs/35849491850)
завершился **до старта каких-либо шагов**. GitHub вернул причину:
`The job was not started because your account is locked due to a billing issue.`
Это блокировка runners аккаунта, не результат тестов кода. Платёжные настройки
не изменялись. После разблокировки workflow можно запустить вручную.

**Windows и macOS в этой сессии фактически не проверены.** Для них подготовлены
команды и CI, но локальные Linux-тесты и имитация legacy locale не считаются
запуском этих ОС. Нельзя обозначать их проверку как успешную до реального CI.

## Оптимизация и миллион узлов

Оптимизированы создание графа, временная сводка и агрегация сообществ;
алгоритмы, веса и точность метрик не менялись. Официальные CSV и результаты
фиксированных синтетических наборов совпали до/после во всех повторах.

Локальные замеры отдельных этапов: дневная сводка 100 тысяч операций
1,190 → 0,547 с; Python-аллокации 59,69 → 25,51 MiB. Сводка 5000 сообществ
9,005 → 0,086 с после устранения повторного обхода всех межкластерных пар.
В полном анализе 10 тысяч узлов медиана 8,58 → 8,17 с; для малых полных наборов
ускорение не доказано. Условия и ограничения измерений — [SCALING.md](SCALING.md).

Отдельный CSR-пробник действительно построил **1 млн вершин / 5 млн рёбер**,
два направления, степени и один матричный шаг: 128 000 008 байт CSR,
291,4 MiB пикового RSS. **Это не полный пайплайн анализа миллиона узлов.**
Публичные лимиты остаются 10k узлов / 50k рёбер / 100k транзакций. Архитектура
большого режима, риски точности, память и этапы приёмки описаны в SCALING.
