# Методика v2.0

Все показатели относятся к наблюдаемой выборке. Роль — рабочая гипотеза, score —
сила правила, приоритет — порядок проверки. Они не устанавливают виновность.

## Метрики

Граф направленный: плательщик → получатель. Узлы сначала добавляются из полного
списка nodes, затем рёбра. Суммы и число переводов проверяются по transactions.
PageRank взвешен суммой KZT. Посредничество рассчитывается приближённо по максимум
128 исходным вершинам, seed=42; расстояние — число переходов. KZT не используется
как длина кратчайшего пути. Охват seed — количество различных seed-предков,
достигающих узел за ≤4 направленных перехода; собственный gid не учитывается.

Пусть `P(x)` — средний процентиль положительного значения среди положительных
значений у неизолированных узлов. Нулевой признак или пустая группа получает 0.
Изолятам явно назначается нулевой приоритет, несмотря на teleport-массу PageRank.

```text
priority_score = .20*P(pagerank) + .20*P(betweenness) + .20*P(seed_reach)
               + .10*P(in_deg) + .10*P(out_deg) + .20*P(max(in_kzt,out_kzt))
```

При равном score порядок определяется числовым gid. Расчёт округляет score до
6 знаков; сохранение CSV фиксирует формат. В карточке показываются вклады.

## Правила и поддержка

Порядок основной роли: coordinator → distributor → transit → consolidator →
terminal → peripheral. Совпавшие альтернативы сохраняются в карточке узла.

Определим `S(x,t)=min(max(x/t,0),1)` и `r=out_kzt/in_kzt` при положительном входе.

| Роль | Условие | role_score до поправки |
|---|---|---|
| coordinator | seed_reach≥2, in_deg≥3, out_deg≥2, P(betweenness)≥.9 | .35*S(seed_reach,4)+.30*P(betweenness)+.20*S(in_deg,6)+.15*S(out_deg,5) |
| distributor | out_deg≥10 и out_tx≥10 | .60*S(out_deg,20)+.25*P(out_tx)+.15*P(out_kzt) |
| transit | Не seed/граница; вход и выход есть; .8≤r≤1.2 | (1−abs(r−1)/.4)*(.5+.5*S(min(in_tx,out_tx),3)) |
| consolidator | Не seed/граница; in_deg≥3; r≤.2 | .50*S(in_deg,6)+.30*(1−min(r/.2,1))+.20*P(in_tx) |
| terminal | Не seed/граница; in_kzt>0 и out_deg=0 | .50+.30*P(in_tx)+.20*S(in_deg,3) |
| peripheral | Более конкретных признаков недостаточно | 0 |

Для seed/границы поддержка умножается на .7; коэффициент обозначает ограниченную
наблюдаемость, а не оценённую статистически вероятность. Пороговые значения
меняются в config/rules.json; аналитические константы формул приведены здесь и
в roles.py. После изменения нужна новая версия правил и повторная проверка.

Граница = depth=4 и out_deg=0. Эти узлы не получают terminal/consolidator из-за
отсутствующего выхода; показывается предупреждение. Seed не получают роли на
основании отношения потоков. Отсутствие конкретной роли не скрывает их
структурный приоритет и не является свидетельством безопасности.

## Сообщества

Louvain применяется к неориентированной проекции. Вес пары — сумма обоих
направлений; основной граф и показ стрелок остаются направленными. Петли
не используются в проекции (их денежный поток остаётся в исходном графе).
Resolution=1, seed=42. Изоляты — отдельные одноузловые сообщества. Стабильные
номера получаются сортировкой групп по минимальному числовому gid.

Внутренний оборот сообщества — сумма исходных направленных рёбер внутри него
без удвоения из проекции. top_gids — JSON-массив строковых ID, top-5 по приоритету.
Гипотеза формируется из численности, seed и распределения ролей, без LLM.
Количество групп не подгоняется под описание организаторов.

## Неопределённость

Полного баланса и внешних поступлений нет; удержание денежных средств, скорость
прохождения и причинная принадлежность переводов не доказаны. Порог 5 000 KZT
скрывает мелкие операции. Данные не содержат истинных ролей: accuracy не измеряется.
Пороги v2 — прозрачная исследовательская эвристика для хакатона, подлежащая
экспертной проверке и проверке устойчивости на других периодах.


## Почему добавлен денежный объём

Структурно одинаковые узлы могут проводить совершенно разные суммы. v2 добавляет
max(вход, выход) как самостоятельный признак, чтобы направление с неполным входом
не получало искусственного нуля. Это наблюдаемый объём, не баланс/ущерб и не сумма
уникальных денег. Процентиль ограничивает влияние единичного крупного перевода.
Веса — экспертная эвристика, не результат обучения и не оптимизация под список gid.

## Временные факты

Дневные вход/выход, число операций и уникальных плательщиков считаются непосредственно
из transactions. Пиковая доля входа = max(дневной вход)/суммарный наблюдаемый вход.
Синхронность означает только общую календарную дату. Без времени суток нельзя
утверждать «одновременно» или устанавливать порядок операций одного дня.

Для совместимости с быстрым транзитом используется FIFO в копейках: доступный
вход распределяется по выходу через 1–2 календарных дня; каждая сумма используется
не более одного раза. Сначала обрабатывается выход текущего дня, затем добавляется
его вход. Суммы старше двух дней исключаются. Показатель — возможное сопоставление,
не трассировка происхождения денег; источники вне выборки и остатки неизвестны.
Пересечение сумм одного дня показано отдельно как сумма min(дневной вход, выход).
Оно не прибавляется к сопоставлению 1–2 дня и не доказывает причинную связь.
Роль transit остаётся **объёмной**: даты дают дополнительное свидетельство,
но не превращают совпадение объёмов в доказательство быстрого транзита.

## Пути и возвратные связи

Для выбранного узла обратный BFS находит seed-предков за ≤4 направленных перехода.
Показывается до пяти кратчайших путей от разных seed со всеми исходными рёбрами,
суммами и числом переводов. Порядок показа — число переходов, затем числовой gid.

Короткие циклы: исходящее ребро и кратчайший возврат за ≤4 перехода, до пяти
примеров. Это не полное перечисление циклов. Для A→B→C нужны ≥2 операции на
каждом звене; исключаются петли и A=C. Полное количество сочетаний считается
точно; до десяти примеров выбираются среди 20 крупнейших входящих/исходящих звеньев.
Так запрос остаётся ограниченным даже у очень больших хабов. Повторяемость
звеньев не доказывает повторение целой цепочки. Все эти пути агрегированы за
период и **не называются хронологическими маршрутами тех же средств**.

## Объяснение сообществ

Гипотеза содержит числа связующих/консолидирующих/распределяющих/транзитных узлов,
seed и граничных узлов. Доля внутреннего оборота = internal / (internal + incoming
+ outgoing), каждый исходный перевод учитывается один раз. В обзоре сообществ
межкластерные рёбра сохраняют направление; клик раскрывает участников.

## Чувствительность рейтинга

Каждый из шести весов отдельно умножается на .8 и 1.2; все веса затем делятся
на их сумму. Для 12 сценариев показывается доля общих участников TOP 20 и
минимальное/максимальное место каждого узла. Это локальный анализ чувствительности,
не доверительный интервал и не проверка accuracy. Пороги ролей, алгоритм Louvain
и случайная выборка betweenness в этих сценариях остаются фиксированными.

## Удаление ключевых узлов

N=1…20 активных узлов удаляются виртуально (исходный результат неизменен).
Сравниваются рейтинг, суммарная степень и 20 случайных выборок без возвращения
с seed=42. Исходные изоляты исключены из кандидатов удаления во всех стратегиях,
но сохранены при подсчёте компонент. Если активных узлов меньше N, используется их число.

Главная метрика не учитывает простую потерю самих удалённых вершин:

```
B = сумма choose(число оставшихся вершин исходной слабой компоненты, 2)
A = сумма choose(размер слабой компоненты после удаления, 2)
потеря связности = 1 - A/B (0, если B=0)
```

Дополнительно: крупнейшая компонента и доля оборота рёбер, затронутых удалением.
Ребро между двумя удалёнными вершинами считается один раз. Слабая связность
игнорирует направление; показатель не предсказывает остановленный денежный поток,
экономический эффект, адаптацию сети или результат реального блокирования.
Случайный диапазон min–max не является доверительным интервалом.
