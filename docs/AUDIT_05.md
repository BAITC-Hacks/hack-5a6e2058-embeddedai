# Проверка каждого пункта ТЗ: приложение 0.5, правила 2.2

> История версии 0.5. Текущий релиз: [аудит 0.6](AUDIT_06.md), [проверки 0.6](VALIDATION_06.md).

Основание — полный [текст ТЗ](../data/ТЗ.md), схема
[датасета](../data/README.md) и дополнительные пояснения
[starter](../data/starter/README.md). Это проверка реализации, а не обещание
баллов: истинных меток ролей в задаче нет.

## Что изменено по результатам этого прохода

1. Основной способ сдачи — завершающийся CLI: одна команда читает исходные
   Parquet, рассчитывает результат, проверяет и публикует все три CSV. Запуск
   веб-сервера не подменяет этот сценарий.
2. Разделены смысловые пороги ролей и относительные признаки датасета. Число
   строк само по себе не должно менять смысл «консолидации» или «транзита».
   Правила 2.2 устраняют чувствительность процентилей к повторению одинаковых
   наблюдений и влияние добавленных изолятов на режим посредничества.
3. Добавлена объяснимая проверка необычных профилей относительно колена:
   фактическое значение, размер группы, квартили и порог. Она не меняет роли
   и TOP и не выдаёт отсутствие сигнала за признак безопасности.
4. Контракт выгрузок проверяется отдельно от успешного выполнения алгоритма:
   покрытие узлов, схема, диапазоны, числовой порядок gid при равном приоритете,
   корректность связей между таблицами.
5. Автоматический запуск CI отключён по указанию владельца. Проверки выполняются
   локальной командой; наличие workflow не принимается за доказательство
   успешного запуска тестов на Windows/macOS.

## Пункты 5–7: вход, выход и пять must-have

Основной прогон после checkout и установки uv:

```text
uv run --frozen --no-dev python analyze.py --data ./data/data --out ./artifacts
```

Процесс завершается: stdout содержит JSON с `status=success`, каталогом,
путями трёх CSV, количеством строк, колонками и SHA-256 каждого файла.
`total_runtime_seconds` включает чтение, анализ и публикацию; установка пакетов
не выдаётся за время алгоритма. При ошибке — ненулевой код и диагностика в stderr.

## Пункт 6: каждое ограничение наблюдаемости

| Особенность исходных данных | Учёт в алгоритме и интерфейсе |
|---|---|
| 444 узла на depth=4 без выхода | `boundary_censored`; terminal/consolidator по отсутствию выхода запрещены; CSV и UI объясняют обрыв; следующий запрос — продолжить обход |
| Только исходящие переводы | Речь идёт о наблюдаемом объёме и относительном пропуске, а не полном балансе/остатке |
| Неполные входящие seed | Seed не получают транзит/консолидацию/terminal на основании отношения потоков; допустимы структурные роли с поправкой наблюдаемости |
| Выход выше наблюдаемого входа | Предупреждение о неполной выборке; это не самостоятельный сигнал аномалии |
| Порог 5000 KZT | Указан в ограничениях и следующих запросах; дробление ниже порога не заявляется обнаруженным |
| 19 seed без рёбер | Сохраняются во всех узлах и кластерах, приоритет структурно равен 0 |
| Ещё 12 seed только получатели | Не отбрасываются; отсутствие выхода seed не превращает их в terminal |
| Несколько слабосвязных компонент | Кластеризация и ранжирование охватывают все компоненты, а не только крупнейшую |
| Нет клиентских атрибутов | Используются только gid, глубина, seed, связи, суммы, число операций, даты |
| Нет ground truth | Не публикуется accuracy; устойчивость TOP и объяснимость не выдаются за проверку истинных ролей |
| Обезличенность и лицензия хакатона | Официальный набор остаётся в приватном checkout; публичное демо показывает синтетику |
| Самопереводы на альтернативном корректном входе | Оборот сохраняется, внешние контрагенты и роли не завышаются; self-only не становится транзитом |

Исходные файлы проверены независимо от заявленных чисел. В них **35** слабых
компонент: **16** с двумя и более узлами плюс **19** изолятов. Вне крупнейшей
компоненты находятся **371** узел, из них **352** с рёбрами. Сумма рёбер равна
**365 890 012,01 KZT**; ТЗ округляет её до целого тенге. Выход превышает вход у
**377** узлов (42 seed и 335 остальных), тогда как текст ТЗ указывает 354.
Числа рассчитываются из предоставленных файлов и не подгоняются под описание.
Глубины всех nodes и edges согласуются с направленным обходом от seed.

## Пункт 8: опциональные функции — без завышения полноты

| Функция | Состояние | Что именно подтверждается |
|---|---|---|
| Обрыв графа | Реализовано | 444 границы не объявляются конечными по отсутствию выхода; истинное поведение вне выборки не восстанавливается |
| Транзит в 1–2 дня | Реализовано | FIFO без двойного использования суммы; не доказывает происхождение денег; внутридневной порядок неизвестен |
| Всплески активности | Реализовано как наблюдаемый признак | Доля входа в пиковый день и дневные суммы; отдельная статистическая модель сезонности не заявляется |
| Синхронные поступления | Реализовано | Число различных плательщиков за календарный день; точная одновременность не утверждается |
| Повторяемые маршруты | Реализовано с ограничением | A→B→C с ≥2 переводами на каждом звене, число сочетаний и ограниченные примеры; повтор целой временной цепочки не доказан |
| Возвратные потоки | Реализовано с ограничением | Направленные короткие циклы и двусторонние связи из наблюдаемых рёбер; не полное перечисление всех циклов |
| Аномальные профили относительно колена | Реализовано в 0.5 | `anomalies.py`: односторонний порог `Q3+3×IQR` отдельно для in_deg, out_deg, volume; минимум 20 активных узлов того же depth |
| Дробление сумм | Не заявляется | Сам факт множества операций не доказывает дробление; операции ниже порога отсутствуют |
| Устойчивость при удалении TOP-N | Реализовано | N=1…20, сравнение приоритета, степени и 20 случайных выборок; связность оставшихся узлов и затронутый оборот |
| AI-ассистент с естественным языком | Не реализовано | Платных API и выдуманного LLM-ответа нет; отсутствие не блокирует must-have |
| Карточка узла | Реализовано | Роль, числа, потоки, связи, ограничения, следующие проверки; Markdown-экспорт, включая необычный профиль |
| Оценка полноты | Реализовано | Конкретные запросы по границе, seed, внешнему входу, другим банкам, порогу и последующим периодам |

Квартили нового профиля используют линейную интерполяцию. Узел сравнивается
только с активными узлами своего колена; изоляты и self-only не входят в группу.
Если в группе менее 20 узлов или IQR равен нулю, система воздерживается от
соответствующего сравнения и объясняет причину. Сигнал требует **строгого**
превышения порога. Отношение потоков, баланс и самопереводы не используются.
Это исследовательское правило без заявлений о precision/recall. На официальном
наборе оно даёт сигналы у 230 узлов; на небольшом синтетическом примере — у 0.
Подгонки под число сигналов нет; CSV ролей и приоритетов от этого слоя не меняются.

| Требование | Проверяемое соответствие |
|---|---|

| Приватность | Gid остаётся обезличенным идентификатором, лишние поля Parquet отбрасываются |
| Осторожные формулировки | «Роль-гипотеза», «наблюдаемый», «конечный в выборке», явные оговорки к приоритету, циклам и профилям |
| Производительность на ноутбуке | Полный прогон официального набора проверяется локально, без вынесения расчёта на VPS |
| Работа локально | После установки пакетов вычисление не требует интернета; LLM отсутствует |
| Свободный стек | Python/FastAPI + TypeScript/Cytoscape; lockfiles и версии описаны |
| Описание миллиона узлов | [SCALING](SCALING.md): пакетная агрегация, CSR/CSC, фоновая обработка, компактные таблицы, ограниченная выдача подграфа, проверки качества приближений |
| Исходный код пайплайна и интерфейса | `src/money_graph`, `web/src`, root `analyze.py` |
| README: одна команда, правила, выход, ограничения, масштаб | [README](../README.md) с отдельным начальным сценарием для жюри |
| Три обязательные выгрузки | [artifacts](../artifacts) плюс воспроизводимый пересчёт |

ТЗ требует **описать** переход к миллиону узлов, а не реализовать его за время
хакатона. Ограничения текущего точного/выборочного графового движка сохраняются
явными. Замер компактной структуры 1 млн узлов/5 млн рёбер в SCALING не выдаётся
за завершённый расчёт ролей на таком объёме.

## Проверки нового слоя и финальный проход

Для профилей выполнены четыре Python-теста: независимость групп по коленам,
исключение изолятов, сохранение роли/приоритета, минимум наблюдений, IQR=0,
строгий порог, нечувствительность к балансу/самопереводам, перестановке строк и
равномерной смене денежной шкалы. Ruff, mypy и TypeScript/Biome прошли.
Браузерные проверки отдельно проверяют воздержание на реальном seed-изоляте и
показ явного числового сигнала без потери основной карточки.

Полная локальная проверка приложения запускается одной командой:

```text
uv run --frozen python scripts/verify.py
```

Без Node.js и Chromium можно отдельно проверить pipeline:

```text
uv run --frozen python scripts/verify.py --backend-only
```

Успешный локальный Linux-прогон не означает фактическую проверку Windows/macOS.
CI отключён по просьбе владельца; прежнее ограничение биллинга GitHub не является
ошибкой алгоритма и не подменяет выполненные проверки.

Итог полного прогона: **177 Python-тестов, 20 локальных браузерных сценариев,
production build — успешно**. Повтор 10 сценариев через публичный HTTPS успешен.
В чистой копии с пустым кешем пакетов одна команда установила зависимости и
выдала три CSV за 76,891 с; на установленном окружении — 6,479 с. Офлайн-повтор
дал побайтно одинаковые CSV. Подробный протокол: [VALIDATION_05.md](VALIDATION_05.md).
