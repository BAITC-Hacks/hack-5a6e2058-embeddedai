# Повторный строгий аудит по ТЗ: план исправлений

Основание: `data/ТЗ.md`, включая пять must-have, ограничения и критерии 25/25/25/15/10.
Проверка выполняется независимо по алгоритмам, входному контракту, интерфейсу и
хранению результатов. Прежний успешный smoke-test не считается доказательством
корректности на граничных случаях.

## Подтверждённые проблемы и порядок работы

| Приоритет | Находка | Исправление | Приёмочная проверка |
|---|---|---|---|
| P1 | Выборочные 128 источников посредничества дают ложные нули на официальном графе | Точное посредничество для небольших графов; sampling только выше документированного порога | Сравнение с exact NetworkX, полный официальный пересчёт <300 с |
| P1 | Поздние ответы поиска/графа смешивают старую ошибку, выделение и новую карточку | Отмена/игнорирование устаревших запросов и согласованное состояние UI | Playwright с искусственно задержанными ответами |
| P1 | Запуск без --data может повторно открыть прошлый несинтетический bootstrap | Явный выбор режима, проверка источников и конфигурации при восстановлении | Перезапуск после разных источников и смены режима |
| P1 | Numeric date принимается как Unix date; лишние колонки и некорректные суммы нарушают контракт | Строгие обязательные типы, дневные даты, проекция схемы, контроль конечности | Вредные/ошибочные Parquet и реальные файлы |
| P1 | Выходной каталог CLI способен заменить посторонние файлы | Безопасная публикация расчёта и генерация примера, понятные ошибки | Внешний input, корень проекта, существующий каталог, неверный PORT |
| P2 | Самоперевод создаёт ложную транзитную роль и контрагентов | Отделить самопереводы от внешних потоков, сохранить оборот и явные факты | Self-only, внешнее поступление + большая петля |
| P2 | Sensitivity использует иной порядок округления, чем основной рейтинг | Единое округление score и правило разрешения равенств | Равные округлённые score при неизменных весах |
| P2 | Повреждённый bootstrap мешает старту; неуспешная загрузка может удалить старые результаты | Атомарная запись метаданных, восстановление bootstrap, очистка после успеха | Коррупция, сбой расчёта/записи, переполнение retention |
| P2 | Старые сохранённые CSV недоступны после смены версии правил | Скачивание опубликованных CSV независимо от возможности открыть старый UI | Download старого результата без пересчёта |
| P2 | Установленный wheel не содержит default rules | Включить каноническую конфигурацию в Python-пакет | Установка wheel в отдельное окружение, CLI без --rules |
| P2 | Синтетика скрыта на mobile; часть важных действий плохо заметна | Видимая маркировка и доступные действия карточки | Laptop/mobile и все состояния ошибок |
| P2 | Документация отстала от добавленного пользователем data/ | Согласовать README, методику, результаты, аудит и материалы сдачи | Чистый checkout, сравнение claims с артефактами |

## Реализация и финальная проверка

1. Сначала воспроизвести каждую находку и зафиксировать regression test.
2. Исправить по разделённым областям кода, не менять пороги/веса ради желаемого рейтинга.
3. Объединить изменения, сверить контракт API/UI и полноту всех пяти обязательных функций.
4. Выполнить общий verify, сравнить CSV с полным набором gid и записать реальные замеры.
5. Проверить чистую установку/CLI, обновить публичный синтетический релиз, пройти HTTPS workflow.
6. Сохранить актуальную методику и результаты, commit/push. Форму платформы сдаёт владелец.

Итоговые статусы и фактические результаты будут внесены после проверки. Новые
необязательные функции не имеют приоритета перед исправлением этих дефектов.
