# AI-аналитик: диалог с контекстом графа

Необязательная функция приложения 0.7. Основной анализ, CLI и обязательные
артефакты воспроизводятся без ключей, интернета и платных сервисов.

## Использование

Строка **«Спросите о графе»** находится над показателями, вне внутренних вкладок.
Можно сразу задать общий вопрос; выбирать узлы необязательно. Enter отправляет,
Shift+Enter переносит строку. Кнопка AI в карточке или очереди переносит к вопросу.

Ассистент различает открытую карточку, явно выбранную группу, фильтры и предыдущий
ответ. Контекст экрана виден под строкой. «Этот узел» относится к карточке,
«выбранные» — к группе, «первые двое из них» — к предыдущему ответу. Открытая
карточка не ограничивает вопрос обо всём графе. При неоднозначности AI уточняет.

| Задача | Пример |
|---|---|
| Начало исследования | «С кого начать проверку этого графа и почему?» |
| Продолжение разговора | «Сравни первых двух из них. Что проверить дальше?» |
| Объяснение карточки | «Почему у этого узла такая роль, что её подтверждает?» |
| Общие получатели | «Кто собирает деньги с этих пятерых?» |
| Общие плательщики | «Кто переводит выбранным узлам?» |
| Поиск | «Пять консолидаторов второго уровня с максимальным входом» |
| Даты | «Что происходило у этого узла с 5 по 10 июля 2026?» |
| Пути | «Есть ли направленный путь от gid A до gid B?» |
| Сообщество | «Объясни структуру сообщества открытого узла» |
| Методология | «Чем приоритет отличается от поддержки роли?» |
| Структурный сценарий | «Как изменится связность при удалении этих двух узлов?» |

Ссылки открывают реальные карточки. Кнопки следующих вопросов заполняют строку;
отправку подтверждает пользователь. Навигация также происходит по нажатию.
«Новый диалог» сбрасывает контекст разговора. Смена набора делает это автоматически.

## Как устроен ответ

1. Сервер проверяет вопрос, выбранные gid и контекст экрана.
2. OpenAI Responses API выбирает ограниченные инструменты: `inspect_graph`,
   `find_nodes`, `inspect_nodes`, `trace_flows`, `inspect_community`, `assess_removal`.
3. Python проверяет аргументы и вычисляет факты по текущему результату анализа.
   Инструменты не меняют граф и не выполняют произвольный код, SQL или HTTP-запросы.
4. Модель получает компактные результаты и при необходимости делает следующую
   проверку. Финальный `answer_question` формирует объяснение, ссылки и предложения.
5. Сервер проверяет формат ответа и ссылки: только существующие gid из контекста,
   истории или результатов инструментов. Интерфейс отдельно показывает
   **интерпретацию AI**, выполненные проверки, вычисленные числа и ограничения.

Модель по умолчанию — [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini),
снимок `gpt-5.4-mini-2026-03-17`; изменяется через `OPENAI_MODEL`.
Для GPT-5 используется reasoning=low с передачей зашифрованного контекста рассуждения
между инструментами при `store: false`.
[Контракт function calling](https://developers.openai.com/api/docs/guides/function-calling).
Используются строгие схемы, один вызов функции за шаг и `store: false`.
Промпт — `assistant_prompts.py`; цикл — `assistant.py`; контекст —
`assistant_context.py`; инструменты — `analyst_tools.py` и `graph_query.py`.

**Вычисленные факты детерминированы; текст модели может ошибаться.** В частности,
валидация ссылок не доказывает правильность каждого предложения. Сверяйте вывод
с числами, путями и карточками. Отказ инструмента явно виден в списке проверок.

## Границы и стоимость

- До 20 исходных узлов и 20 результатов за одну проверку; ответы инструментов
  ограничены 25 тыс. символов. Ограничение/усечение указано в результате.
- До четырёх вызовов инструментов и пяти обращений к модели на вопрос; 75 секунд
  на обработку, до 30 секунд на сетевое ожидание одного ответа. Повтор одинаковой
  проверки отклоняется. Платные сетевые вызовы автоматически не повторяются.
- Один вопрос одновременно; до 60 вопросов и 180 обращений к модели в час
  на процесс. Эти лимиты общие для пользователей; при нескольких репликах
  нужен общий шлюз лимитов. Перезапуск сбрасывает счётчики.
- Общие контрагенты по умолчанию прямые и общие для **всех** выбранных узлов.
  Косвенные связи до четырёх шагов — по запросу. Путь не доказывает движение
  тех же денег, а суммы его рёбер не являются сквозным денежным потоком.
- Даты поддержаны для дневных агрегатов до трёх узлов (до 31 показанного дня,
  точные итоги запрошенного интервала). Общий рейтинг по датам не пересчитывается.
- Роли — гипотезы, приоритет — порядок проверки, role_score не вероятность
  правонарушения. Неполнота выгрузки сохраняется во всех ответах.
- Нет внешнего обогащения, определения личности и автоматической блокировки счетов.

## Данные, история и доступ

**В OpenAI передаются вопрос, контекст экрана, краткая недавняя история и запрошенные
производные факты графа**: метрики, связи, пути или дневные агрегаты. Исходные
Parquet-файлы и весь граф целиком не отправляются. Локальные заметки очереди
не отправляются. Не включайте в вопрос сведения, которые нельзя передавать провайдеру.
`store: false` не заменяет политики обработки и служебного хранения провайдера.

История находится только в памяти процесса, без записи вопросов в журналы или файлы:
до 50 диалогов, до четырёх последних обменов и 20 тыс. символов на диалог.
Продолжение доступно 30 минут после последнего ответа; просроченные записи очищаются
при очередном обращении, все записи исчезают при перезапуске. Случайный идентификатор
диалога привязан к набору и отчёту расчёта. Браузер не сохраняет его после обновления.
«Новый диалог» начинает новый контекст; прежняя серверная запись подчиняется тем же лимитам.

Настройка ключа для Linux/macOS и Windows приведена в [README](../README.md#ai-ассистент-аналитика).
`.env` автоматически не загружается. Ключ остаётся на сервере, новый SDK не нужен.
Публичный платный endpoint защищается отдельным `MONEY_GRAPH_ASSISTANT_TOKEN`.

HTTP: 401 — код доступа; 409 — устаревший/чужой диалог; 422 — неверный вопрос
или контекст; 429 — параллельный запрос/лимит; 502 — неверный ответ провайдера;
503 — нет ключа/доступа/баланса; 504 — тайм-аут. Ошибка не превращается в успешный
ответ. Отмена ожидания в браузере не гарантирует отмену начатого запроса у провайдера.
Автоматические тесты подменяют OpenAI и не расходуют токены.
