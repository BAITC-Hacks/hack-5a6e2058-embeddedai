# Демонстрация: пять минут

Сценарий для приложения **0.8.0**, правил **2.2**. Актуальные замеры и выполненные
проверки — [VALIDATION_08.md](VALIDATION_08.md); условия ролей — [METHODOLOGY.md](METHODOLOGY.md).
Один готовый слайд — [SOLUTION.svg](SOLUTION.svg); три предметных разбора с точными
метриками, порогами и командой выгрузки карточек — [DEMO_NODES.md](DEMO_NODES.md).

## Подготовка

Для показа официального набора из приватного репозитория:

```bash
uv run --frozen --no-dev python scripts/start.py --data ./data/data --port 3010
```

Откройте `http://127.0.0.1:3010`. Убедитесь, что выбран нужный расчёт: 2248 узлов,
3119 связей, 4840 транзакций, 88 сообществ. Если браузер восстановил другую
сохранённую загрузку, загрузите три файла из `data/data/` через интерфейс.

Открытая ссылка https://cca8f159.nip.io показывает явно обозначенную синтетику:
80 узлов и 95 связей. Официальные данные демонстрируйте локально либо в закрытой
сессии жюри; не загружайте их в публичное демо для подготовки презентации.

Не заучивайте старые позиции и роли gid из версии 2.0: точное посредничество
в 2.1 изменило часть рейтинга. Выбирайте примеры из текущего расчёта. Заранее
откройте CSV и подготовленные [три карточки](DEMO_NODES.md). Основной маршрут:
`100000003684369100` → `100000003635170100` → `100000003220685100`.
Первый пример объясняет порядок ролей, второй — разницу объёмного и временного
транзита, третий — обрыв наблюдения. Эти gid выбраны из результата только для
сценария показа; алгоритм не содержит заранее выбранных ответов.

## Сценарий

1. **0:00–0:35 — задача и воспроизведение.** В терминале выполнить
   `uv run --frozen --no-dev python analyze.py --data ./data/data --out ./artifacts`,
   показать `status: success` и три CSV в manifest. Затем открыть локальный интерфейс,
   показать 2248 узлов и фактическое время расчёта. «От 81 seed к очереди проверки
   всей наблюдаемой сети». В карточке методики указать точный расчёт посредничества
   для этого объёма и отсутствие платных внешних зависимостей.
2. **0:35–1:30 — первый приоритет.** Открыть текущий первый узел TOP. Сопоставить
   evidence с потоками и порогами роли. Раскрыть «Вклад в приоритет и правила»:
   показать денежный объём, поддержку до/после поправки и диапазон места при
   изменении весов. Подчеркнуть, что поддержка правила — не вероятность виновности.
3. **1:30–2:25 — доказательства.** Нажать «Пути, циклы и хронология» прямо под
   evidence. Перейти к `100000003635170100`: 94.41% выход/вход достаточно для
   объёмной роли transit, но за следующие 1–2 дня сопоставлено только 23.84% входа.
   Показать взаимные переводы с `100000004209339100`, дневные вход/выход
   и точные суммы по датам. Объяснить разницу между наблюдаемым путём и
   недоказанным движением тех же денег; отсутствие короткого цикла не исключает
   длинных контуров.
4. **2:25–3:15 — произвольный gid жюри.** Вставить полный идентификатор без
   округления. Показать окружение со стрелками и суммы по нажатию на связь,
   перейти к сообществу. Затем открыть `100000003220685100`, узел уровня 4:
   отсутствие выхода не означает удержание; следующий запрос — продолжение обхода.
   При вопросе об изолятах показать сохранённый seed без рёбер.
5. **3:15–4:15 — очередь аналитика и AI.** В «Очереди» выбрать роль «Консолидатор»,
   отсортировать по входящему объёму, показать, что доступны и узлы за пределами
   TOP 50. Выбрать несколько узлов, добавить локальную заметку. При включённом
   AI в строке над графом спросить «Кто переводит этим узлам?», затем «Объясни
   первый результат». Сверить выполненные проверки, направление и
   ссылки на реальные карточки. Отсутствие общих плательщиков — допустимый
   результат, а не причина придумывать связь. Если сеть недоступна, показать
   очередь и вычисленную устойчивость правил во вкладке «Проверки».
6. **4:15–5:00 — передача аналитику.** Скачать список выбранных узлов, справку
   с SHA-256 источников и три обязательных CSV. Открыть `artifacts/report.html`
   без сервера. Показать одну команду расчёта и `uv run --frozen python scripts/verify.py`,
   [диаграмму](SOLUTION.svg), три автономные карточки и ограничения. Уточнить: нет истинной разметки, обогащения клиента,
   автоматической блокировки или платного API в основном сценарии.

По дополнительному вопросу: «Проверки» → удалить пять узлов и сравнить с degree
и 20 случайными выборками; показать устойчивость ролей при изменении порогов и
сообществ при смене seed/resolution. Эти эксперименты не являются accuracy.

Для показа AI настройте ключ по [инструкции](ASSISTANT.md) до начала демо.
На публичной синтетике выберите первые пять seed по gid в очереди: вопрос
«Кто собирает деньги с этих пятерых?» даёт проверяемые общие входящие связи.
Это сценарий демонстрационных данных, а не зашитый ответ алгоритма.

## Контроль перед показом

- Проверить маркировку и размер выбранного набора, затем обновить страницу:
  ссылка должна восстановить тот же расчёт.
- Не показывать старые CSV рядом с карточкой правил 2.2; при необходимости
  пересчитать `uv run --frozen money-graph analyze --data data/data --out artifacts`.
- После неизвестного gid исправить значение или выбрать узел из TOP. После
  временной ошибки начальной загрузки нажать «Повторить загрузку».
- Если времени мало, сохранить произвольный поиск, объяснение роли, границу
  наблюдения и скачивание CSV; дополнительные эксперименты показать по запросу.

Сдачу через платформу выполняет участник. Название и описание подготовлены в
[SUBMISSION.md](SUBMISSION.md).
